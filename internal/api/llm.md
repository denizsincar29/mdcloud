# mdcloud API — инструкция для ассистентов

Облако markdown-документов. Базовый адрес: `https://mdcloud.denizsincar.ru`

Документ живёт по адресу `https://mdcloud.denizsincar.ru/<логин>/<путь>` и
показывается читаемой страницей: markdown, формулы (LaTeX в `$…$` и `$$…$$`,
AsciiMath в обратных кавычках), шахматные доски, комментарии.

## Авторизация

Каждый запрос от имени аккаунта несёт заголовок:

```
Authorization: Bearer <ключ>
```

Ключ владелец выписывает сам: на сайте кнопка «Учётная запись» → «API-токены» →
«Выписать ключ» со сроком (день, месяц, бессрочно). Ключ показывается один раз —
в базе лежит только его отпечаток. Ключ даёт полный доступ к аккаунту: не
публикуй его в открытых местах и не вставляй в чужие страницы.

Запросы без ключа тоже возможны — они видят только публичные документы
(`public`), у остальных ответ 404.

## Сохранить документ

```
POST /api/docs
Content-Type: application/json
Authorization: Bearer <ключ>

{
  "path": "ДЗ/ИИ/задачи",
  "content": "# Задачи\n\n- [ ] первая\n",
  "public": true
}
```

Поля:

- `path` — обязателен. До 5 вложенных папок, сегменты из букв, цифр, `-`, `_`,
  `.`, `+`, `(`, `)`, без пробелов; без ведущего слэша. Адресом может быть и
  «ДЗ/ИИ/задачи», и «ДЗ/ИИ/задачи.md» — как удобнее.
- `content` — markdown документа.
- `title` — заголовок для списков; не указан — берётся имя файла.
- `public` — `true` открывает документ всем, `false` закрывает. По умолчанию
  документ закрыт. Вместо флага можно прислать `"visibility": "public"` или
  `"visibility": "private"` — это одно и то же.
- `comments_on`, `comments_require_auth` — комментарии включены/только для
  вошедших.

Ответ: `201` — документ создан, `200` — существующий обновлён. Тело — сам
документ (`owner`, `path`, `title`, `visibility`, `url`, `updated_at`).

Обновление заменяет только присланные поля: чтобы дописать текст, сперва
прочитай документ (`GET`), потом отправь новый `content` целиком — в облаке
нет «дописать в конец», `content` всегда целый документ.

Предел размера — 2 МБ на документ.

## Прочитать

- `GET /api/docs/<логин>/<путь>` — документ с содержимым. Закрытый чужой
  отвечает 404.
- `GET /api/docs/<логин>` — список документов владельца (без содержимого); под
  ключом владельца видно и закрытые.
- `GET /api/docs` — свои документы.
- `GET /api/me` — кто я по этому ключу.

## Изменить и удалить

- `PUT /api/docs/<логин>/<путь>` — то же, что `POST /api/docs`, но адрес в
  пути; тело такое же, без `path`.
- `DELETE /api/docs/<логин>/<путь>` — удалить документ.

## Комментарии

- `GET /api/comments/<логин>/<путь>` — комментарии к документу.
- `POST /api/comments/<логин>/<путь>` — `{"body": "текст"}`; под ключом имя
  автора подставляется само.
- `DELETE /api/comments/<id>` — удалить свой комментарий или любой под своим
  документом.

В тексте комментария ссылка на строку документа пишется как `{line 5}` — на
странице она станет ссылкой «строка 5», а `[здесь]{line 5}` — ссылкой со
словом «здесь». Номера строк считаются по исходнику документа, включая
frontmatter.

## Ключи

- `GET /api/tokens` — список ключей (без самих ключей, только метки, сроки и
  когда ключом последний раз пользовались).
- `POST /api/tokens` — `{"label": "дайджест", "days": 30}`; `days` не указан
  или `0` — ключ бессрочный. Значение ключа приходит в ответе один раз.
- `DELETE /api/tokens/<id>` — отозвать ключ.

## Ошибки

Тело любой ошибки — `{"error": "по-русски, что не так"}`, код говорит сам за
себя: `400` — не разобрал запрос (путь, размер, видимость), `401` — нужен
ключ, `403` — чужой аккаунт, `404` — нет такого документа (в том числе чужой
закрытый), `409` — конфликт, `413` — документ больше предела, `415` — тело не
`application/json`, `429` — слишком часто.

## Пример: сохранить и открыть

```
curl -X POST https://mdcloud.denizsincar.ru/api/docs \
  -H "Authorization: Bearer $MDCLOUD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"path":"заметки/сентябрь","content":"# Сентябрь\n","public":true}'
```

Ссылка на документ — в поле `url` ответа.
